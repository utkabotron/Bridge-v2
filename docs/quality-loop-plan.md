# Петля «аналитика → качество перевода»: план

Аудит 2026-10-06. Исходное состояние: v2.6 = 4.59, v2.9 = 4.54, 12% плохих — правки
промпта не дают эффекта; глоссарий чатов делает хуже (пара 29: 33% плохих).
Контрольная метрика: доля оценок ≤3 по парам моста (без DM и безпарных), по неделям.

Отмечать `[x]` по факту выкатки на прод, с датой.

## Шаг 1 — глоссарий (главный рычаг) — выкачено 2026-10-06

- [x] Строитель профиля: в глоссарий только имена собственные (школы, платформы, места,
      организации, программы, праздники); нарицательные запрещены явно
- [x] Строитель получает только оригиналы, не свои прошлые переводы (разрыв самоподкрепления)
- [x] Новые записи глоссария проходят LLM-валидацию до слияния в профиль
- [x] Ночная сверка: запись глоссария, встреченная в ≥3 плохих переводах → удаляется,
      попадает в `glossary_removed`, строитель её больше не добавляет
- [x] Разовая чистка существующих глоссариев (`--prune-glossaries`), начиная с пары 29
- [x] `format_chat_context`: «устойчивые написания названий», а не «use these transliterations»
- [x] Сброс Redis `chat_profile:{id}` после каждого изменения профиля
- [x] Ключ кэша переводов включает версию промпта и контекст чата (иначе правка глоссария
      ждёт 24 ч)
- [x] Удалённые записи видны в Telegram-уведомлении строителя

Проверка: пара 29 за неделю после выкатки — доля плохих с 33% к ≤15%.
Чистка 06.10: из глоссария пары 29 снято 13 нарицательных из 19, `סוכה` → «сукка».

- [x] Ночные «добавьте правило в промпт» отключены; правки глоссария — шаг 1.
      Few-shot-примеры из оценок ≥4.8 — следующий A/B после v2.10 vs v3.0 (одно изменение за раз)
- [x] A/B промпта через feature flag по части пар; оценки с версией; сравнение через 7 дней

      на промпте v2.10; v3.0 — следующий эксперимент. Строка «A/B» в дайджесте,
