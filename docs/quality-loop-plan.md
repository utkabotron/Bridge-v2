# Петля «аналитика → качество перевода»: план

Аудит 2026-10-06. Исходное состояние: v2.6 = 4.59, v2.9 = 4.54, 12% плохих — правки
промпта не дают эффекта; глоссарий чатов делает хуже (пара 29: 33% плохих).
Контрольная метрика: доля оценок ≤3 по парам моста (без DM и безпарных), по неделям.

Отмечать `[x]` по факту выкатки на прод, с датой.

## Шаг 1 — глоссарий (главный рычаг)

- [ ] Строитель профиля: в глоссарий только имена собственные (школы, платформы, места,
      организации, программы, праздники); нарицательные запрещены явно
- [ ] Строитель получает только оригиналы, не свои прошлые переводы (разрыв самоподкрепления)
- [ ] Новые записи глоссария проходят LLM-валидацию до слияния в профиль
- [ ] Ночная сверка: запись глоссария, встреченная в ≥3 плохих переводах → удаляется,
      попадает в `glossary_removed`, строитель её больше не добавляет
- [ ] Разовая чистка существующих глоссариев (`--prune-glossaries`), начиная с пары 29
- [ ] `format_chat_context`: «устойчивые написания названий», а не «use these transliterations»
- [ ] Сброс Redis `chat_profile:{id}` после каждого изменения профиля
- [ ] Ключ кэша переводов включает версию промпта и контекст чата (иначе правка глоссария
      ждёт 24 ч)
- [ ] Удалённые записи видны в Telegram-уведомлении строителя

Проверка: пара 29 за неделю после выкатки — доля плохих с 33% к ≤15%.

## Шаг 2 — честные метрики

- [ ] `message_events` += prompt_version, cache_hit, translation_passthrough, translation_failed,
      translation_error
- [ ] `translation_evaluations` += prompt_version, source (bridge | direct | fallback),
      chat_pair_id, target_language, message_type
- [ ] LLM-выборка берёт язык пары (`coalesce(cp, u)`), не аккаунта
- [ ] Средние и предложения считаются только по source = bridge; DM и fallback — отдельной строкой
- [ ] Ночной и недельный отчёт: разбивка по парам, языкам, типам; худшая пара названа
- [ ] `nightly_analysis_runs.summary` хранит prompt_version
- [ ] Дашборд `/api/reports` показывает разбивку по парам

Проверка: в недельном отчёте есть таблица по парам; v2.10 сравним с v2.9 по тегу.

## Шаг 3 — петля промпта

- [ ] Ночные «добавьте правило в промпт» отключены; вместо них — правки глоссария и
      few-shot-примеры из оценок ≥4.8 по чату
- [ ] A/B промпта через feature flag по части пар; оценки с версией; сравнение через 7 дней
- [ ] `/weekly-improve` пишет обратно, что сделано (`analytics_changelog`), o3 это читает
- [ ] `weekly_insights.prompt_draft` показывается человеку и следующему o3

## Шаг 4 — контекст переводчику

- [ ] Имя отправителя

- [ ] Оценщик видит тот же контекст и глоссарий (отличает ошибку модели от ошибки профиля)
